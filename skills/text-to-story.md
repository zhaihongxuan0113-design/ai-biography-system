# 技能：text-to-story（AI 故事整理 · 保留说话风格）

> 对应工作流步骤：auto-process.yml 步骤 2 ｜ 实现脚本：.github/scripts/text_to_story.py
> 调用 DeepSeek API（模型 deepseek-chat，密钥存于仓库 Secrets：DEEPSEEK_API_KEY，不在任何文件里明文出现）

## 功能
把逐字转写稿整理成可入书的传记故事：只梳理逻辑顺序、拆分段落，不改写措辞、不替换口语词，保留长者原始语气、说话节奏与个人口吻。

## 输入
- 路径：`tests/transcripts/` 下的转写文件
  - 模拟测试：`第X周_问题N_测试长者001_转写.md`
  - 真人测试：`真人测试_第X周_问题N_转写.md`（带「真人测试_」前缀）

## 输出
- 路径：`tests/stories/`
- 命名：与转写稿一一对应
  - 模拟测试：`第1周_问题1_测试长者001_故事.md`
  - 真人测试：`真人测试_第1周_问题1_故事.md`
- 结构：
  - 标题（含周次、问题）
  - 正文按回忆主题分段，每段一个小标题
  - 结尾单独一段「原话金句」，保留长者原话

## 整理规则（严格读取，不得自行修改）
脚本在运行时读取 `docs/语气保留指南.md` 的「第二步：AI 整理故事时，保留说话风格和情感」整节，作为系统提示词原样传给 DeepSeek，其中包含：
1. 保持第一人称，保留「我」的口吻；
2. 保留所有方言词和口头禅，可加小括号注明意思；
3. 只删除重复和跑题的部分，不替换任何原词、不美化、不总结升华；
4. 保留情绪标注，或自然写出「说到这里，老人家笑了」；
5. 改完对照原稿检查：每句都能在原稿里找到出处。

脚本在原规则之后追加以下**真人场景补充规则**（与指南原文冲突时以补充规则为准）：
1. 允许内容跑题：保留真实的聊天感，跑题内容不删除，可顺其自然归入相近的段落；
2. 保留老人常用的口头禅、俗语、地方话，不解释、不替换、不翻译，必要时在旁边用小括号注明意思；
3. 只梳理逻辑顺序、拆分段落，绝不改写措辞、不替换口语词、不补充虚构细节；
4. 每段加一个小标题，概括该段回忆主题；
5. 结尾提炼一句老人的原话作为金句，一字不改。

## 参数
- 模型：`deepseek-chat` ｜ 温度：0.5 ｜ 最大输出：3000 tokens
- 系统提示词 = 语气保留指南第二步原文 + 真人场景补充规则 + 输出格式要求（小标题、结尾金句）

## 幂等与重试
- 已存在同名故事文件自动跳过；
- 工作流内自动重试 2 次（共 3 次），仍失败则向访谈 Issue 评论错误原因；
- 每次调用的 token 消耗写入 `tests/metrics.json`，供成本统计。

## 验证方法
- 抽查 10 句：每句均可在对应转写稿中找到出处；
- 检查口头禅/方言保留率 ≥ 80%；
- 检查无原稿之外的虚构细节、每段有小标题、结尾有原话金句。
